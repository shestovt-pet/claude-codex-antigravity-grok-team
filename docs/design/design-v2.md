Тексты исчерпания в codex.exe: «You’ve hit your usage limit», «Try again at …», «Try again later.»; в app-server — codexErrorInfo UsageLimitExceeded.
- Codex-мост сейчас разрешает продолжение только после status=done и держит блокировку папки только в своём процессе.

## Архитектура

**Репозиторий C:\most (git, локально).** main — только принятое. Структура:
```
AGENTS.md            общие правила для Codex и Antigravity (читаются автоматически)
rules/               правила: common.md, claude.md, design-gate.md, lessons-policy.md
lessons.md           журнал уроков
servers/antigravity/ адаптер Antigravity (бывший most)
servers/codex/       адаптер Codex (бывший claude-codex)
servers/team/        сервер команды: статус, квоты, правила, изменения инструментария
common/              общий формат ответов, словарь статусов, квоты, блокировки
skill/helpers/       исходник скилла Claude
tests/               поддельные agy и codex, автотесты
.work/<change>/      рабочие копии изменений (git worktree, вне main)
live/                развёрнутая принятая версия — отсюда Claude запускает серверы (не в git)
```
Два адаптера — отдельными процессами (надёжнее, у каждого своя логика записи), общий только формат/статусы/блокировки (модуль common). Третий маленький сервер `team` — только чтение состояния и узкие git-операции.

**Git-операции делает сервер team от имени пользователя** (у Codex в песочнице их не выйдет): `team_change` с действиями start (ветка + рабочая копия .work/<имя>), commit, review (разослать дифф конкретной редакции двум другим участникам), verdict (записать вердикт, привязанный к хешу дерева), merge (только если три вердикта «ПРИНЯТО» на ОДНО И ТО ЖЕ дерево и main не ушёл вперёд; иначе — новое ревью), deploy (собрать принятое в live/ через временную папку и замену, отдать «версия на диске / версия в процессе, нужен перезапуск Claude»). Codex правит файлы только в рабочей копии (cwd = .work/<имя>, write=true). Antigravity ничего не пишет. Живую папку live/ меняет только deploy.

## Решения по пунктам

### 1. Язык и формат

- Идентификаторы — английские (совместимость клиентов и моделей), человекочитаемое — по-русски, транслит запрещён. Оригинал чужой ошибки сохраняется рядом с русским объяснением. Граница обещания: сообщения наших серверов и отчёты Claude (интерфейсы чужих приложений не переводим).
- Серверы и инструменты: `antigravity_status/send/result/apply/cancel`, `codex_status/send/result/cancel`, `team_status/rules/change`. У каждого русский title (SDK 1.29 поддерживает; показывает ли его Claude Desktop — проверяется живьём, не обещается) и русское описание. Параметры — английские: folder, file, lines, mode, model, stage, work.
- Первая строка каждого ответа: `Codex · поручение 7f3a · ИДЁТ · 2 мин 10 с`. Ответ — текст, не JSON.
- Словарь состояний исполнения: В ОЧЕРЕДИ, ИДЁТ, ЖДЁТ КВОТУ (до …), ОТВЕТ ПОЛУЧЕН, НЕ УДАЛОСЬ, ОТМЕНЯЕТСЯ, ОТМЕНЕНО, ОСТАНОВКА НЕ ПОДТВЕРЖДЕНА, ПОТЕРЯНО. Состояния переноса: ПЕРЕНОСИТСЯ, ПЕРЕНЕСЕНО, РЕЗУЛЬТАТ ПЕРЕНОСА НЕЯСЕН. Состояния приёмки (ставит Claude): ПРОВЕРЕНО ПОЛНОСТЬЮ / ВЫБОРОЧНО, ПРИНЯТО ПОЛЬЗОВАТЕЛЕМ. Для Codex с записью — «ИЗМЕНЕНИЯ УЖЕ ВНЕСЕНЫ в <папку>», переноса нет.

### 2. Прогресс к итогу

- У многошаговой работы — status.md в папке работы. Пишет его только Claude (один писатель — нет гонок); серверы только читают.
- В нём: цель, критерий готовности, этапы с весами и критерием приёмки, для принятого этапа — чем проверено и ссылка на версию.
- Показатель называется честно: «принято N % плана». При изменении плана веса пересчитываются с пояснением, процент может уменьшиться.
- Если поручение относится к зарегистрированной работе, `stage` и `work` обязательны; серверы повторяют этап во всех ответах, team_status показывает все работы. Одиночное поручение — без процента.
- Строка пользователю: `Принято 60 % плана · этап 4 из 7 — вычитка главы 2 · сделано: … · это закрывает: … · осталось: …`

### 3. Проблема → улучшение системы

- lessons.md: воспроизводимый случай (цитата), первопричина, область действия правки, где закрыто (сервер / правила / скилл / шаблон поручения / тест), остаточное ограничение, проверка фактического поведения установленной версии (не только «правило записано»).
- Каждое замечание при ревью помечается: блокирующее / улучшение; разовое / системное. Блокирующие закрываются в текущем цикле. Системные улучшения, не блокирующие результат, заносятся в lessons.md как открытые, с условием возврата, и не выдаются за исправленные.
- Повтор урока: сначала проверить, доставлено ли правило (версия правил в team_status, загружена ли новым сеансом), потом — сама правка.
- В поручения не вкладывается весь журнал: короткие действующие правила + уроки по типу задачи.

### 4. Ворота замысла

- Когда: последствия ошибки существенны или необратимы; меняется общий инструментарий (серверы, правила, скилл); высокая неопределённость подхода; или больше ~30 минут работы. Мелкое — без ворот.
- Оба проверяющих получают одну неизменяемую редакцию замысла (файл с хешем) + исходный запрос пользователя + ограничения среды, с одинаковым вопросником. Роли: Antigravity — критик замысла и содержания; Codex — инженер: осуществимость, проверяемость.
- Claude отвечает на каждое замечание (принято / отклонено — почему, с доказательством). Исправление важного замечания подтверждает его автор; архитектурные изменения снова видят оба. Выход из спора: после двух кругов несогласия — прямой вопрос пользователю с вариантами.
- Недоступность участника (квота): независимая работа продолжается, приёмка изменения инструментария ждёт — голос одного участника не заменяется другим.

### 5. Токены

- Claude — дирижёр и судья; объёмная работа — помощникам: код, тесты, поиск по диску → Codex; длинные тексты, фактура, полная вычитка больших файлов → Antigravity; второе мнение от обоих — по риску, не всегда.
- Claude не читает большие файлы целиком, если помощник даёт сводку со ссылками на строки; ответы серверов компактные, постранично.
- team_status показывает квоты с источником и временем снимка: Codex — app-server (5 ч и неделя по длительности окна: 300 / 10080 мин), запасной источник — rollout-журнал; «данные не предоставлены», если окна нет. Antigravity — цифр нет: активность (поручения, расход токенов по ответам agy) и последнее исчерпание. Claude — со страницы claude.ai/settings/usage через встроенный браузер, если пользователь однажды вошёл там в аккаунт; иначе «не видно».
- Режимы Claude: квота неизвестна или ≥ 60 % → экономный (по умолчанию делегировать, короткие отчёты); ≥ 85 % → не начинать крупных шагов. Состояние (status.md: следующий шаг) сохраняется ДО каждого дорогого шага независимо от процента.
- Модель Antigravity выбирается из фактического списка agy, а не из вписанных имён.

### 6. Скилл

- Один универсальный тонкий скилл `helpers` (замена rabota-s-antigravity): неизменные основы безопасности + «в начале работы вызови team_rules и следуй им». Изменчивые правила живут в репозитории и приходят через team_rules без переустановки скилла. Переустановка (карточка, клик пользователя) нужна только при смене основ — редко; версия скилла сверяется с версией правил в team_status.
- Отдельный скилл под Codex не делается; особенности каждого помощника — разделами правил.

### 7. Исчерпание квоты

- Классификация — по структурированной ошибке исполнителя, не по тексту ответа: agy — поле status/error JSON; Codex — turn.failed с текстом usage limit (оба варианта апострофа) и/или codexErrorInfo, подтверждение через rateLimits.
- Поручение → ЖДЁТ КВОТУ с временем сброса (из «Try again at» / resetsAt; неизвестно — проба раз в 30 минут, не больше 12 проб), хранится на диске с номером попытки, блокировкой и владельцем. Повтор: Antigravity — то же поручение заново (он ничего не пишет, перенос делает Claude); Codex только чтение — resume по сохранённому threadId; Codex с записью — автоматически не повторяется: «нужна проверка частичных изменений», решает Claude.
- Работает, пока открыт Claude Desktop (серверы — его дочерние процессы). При следующем запуске очередь поднимается сама, без двойного запуска (проверка владельца). Постоянной службы Windows не делаем — сознательное ограничение.
- Подмена исполнителя — только для обычного анализа (fallback), никогда для обязательного ревью и для записи.
- Claude: перед длинной работой ставит запланированное сообщение в эту же беседу на время сброса своей квоты (если известно) или через 5 ч; при завершении работы снимает. Состояние — в status.md.

### 8. Без мастер-чата

- Состояние живёт в репозитории и у серверов, а не в переписке: любой чат Cowork видит его через team_status / team_rules без подключения папок; приложения Codex и Antigravity, открытые в C:\most, читают AGENTS.md автоматически.
- Любая правка инструментария: team_change start → правка в .work/<имя> → commit → review обоим (дифф конкретного дерева) → три вердикта на одно дерево → merge → deploy в live/ → перезапуск Claude (сообщается явно). Новая правка после вердиктов их аннулирует.
- Попутно: глобальный AGENTS.md Antigravity и Codex получают короткую ссылку на общий порядок; GEMINI.md Antigravity перекодируется (без изменения текста).
