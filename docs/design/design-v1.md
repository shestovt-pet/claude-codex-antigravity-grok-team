## Решения по пунктам

### 1. Единый язык и формат уведомлений

Правило: всё, что читает человек (описания инструментов, ответы, статусы, ошибки, отчёты), — по-русски. Всё, что является идентификатором (имена серверов, инструментов, параметров, файлов, веток), — по-английски, коротко и понятно. Транслит запрещён везде. (Причина: имена инструментов MCP допускают только латиницу — кириллицу туда поставить нельзя.)

Мосты сливаются в один сервер `helpers` (замена `most` и `codex`; старый `antigravity` удаляется из настроек Claude). Инструменты:

| Инструмент | Русское название (title) | Что делает |
|---|---|---|
| `status` | Состояние помощников | версии, квоты, очередь, идущие задания, работы и их прогресс |
| `send_task` | Поручить помощнику | helper = antigravity / codex; mode = edit / review / text / task |
| `get_result` | Результат поручения | статус, сводка, правки постранично, замечания |
| `apply_result` | Перенести результат | правку — в исходный файл, текст/замечания — новым файлом |
| `cancel_task` | Остановить поручение | |

Каждый ответ моста начинается одной строкой по шаблону:
`Antigravity · поручение 7f3a · ГОТОВО · 2 мин 10 с`
Словарь статусов фиксирован: В ОЧЕРЕДИ, ИДЁТ, ГОТОВО, НЕ УДАЛОСЬ, ЖДЁТ КВОТУ, ОТМЕНЕНО, ПОТЕРЯНО, ПЕРЕНЕСЕНО. Затем — строка этапа работы (п. 2), затем суть, последней строкой — «Дальше: …».
Отчёты Claude пользователю — по тому же шаблону.

### 2. Статус, показывающий приближение к итогу

У каждой многошаговой работы есть файл `status.md` в её папке: цель, критерий готовности, этапы с весом (в сумме 100) и критерием «этап принят», текущий этап, следующий шаг.
- Процент готовности = сумма весов ПРИНЯТЫХ этапов. Отправленное, идущее и «получено, не проверено» процент не увеличивает (честность: запланированное не выдаётся за сделанное).
- `send_task` принимает необязательный `stage` («4/7 вычитка главы 2») и `work` (путь к status.md); мост повторяет этап во всех своих ответах, `status` показывает все работы и их проценты.
- Строка для пользователя: `[██████░░░░ 60 %] Этап 4 из 7 — вычитка главы 2 · сделано: … · это даёт: … · осталось: …`

### 3. Каждая найденная проблема — улучшение системы

- Журнал уроков `lessons.md` в общем репозитории (п. 8): номер, дата, что случилось (цитата), первопричина, класс (разовая / системная), где закрыто (мост / правила / скилл / шаблон поручения / тест), коммит, проверка от повтора (автотест или пункт чек-листа).
- Правило: каждое замечание при взаимной проверке классифицируется. Системное — в том же цикле даёт правку инструментария и проверку от повтора; цикл не закрыт, пока правка не принята всеми тремя. Неустранимое (ограничение платформы) — в «Известные ограничения» с обходом.
- Повтор уже записанного урока — сигнал, что прошлая правка не сработала: разбор заново, а не вторая заплатка.
- Режим review моста требует от помощника у каждого замечания пометку «разовое / системное» и предложение, где закрыть.

### 4. Проверка замысла, а не только результата

- Ворота «Замысел» перед исполнением, если выполняется хоть одно: больше 3 шагов; дольше ~30 минут; затрагивает правила/мост/скилл/канон хроники; необратимое действие.
- Замысел — до страницы: цель, критерий готовности, подход, отвергнутые альтернативы, риски, этапы с весами.
- Отправляется обоим помощникам параллельно (review, только чтение) с одинаковым вопросником: что упущено; где проще; где риск; какой критерий непроверяем; что бы вы сделали иначе.
- Роли для разнообразия взгляда: Antigravity (Gemini — другая семья моделей) — критик содержания и замысла; Codex — инженер: осуществимость, проверяемость, тесты.
- Claude отвечает на каждое замечание в файле замысла (принято / отклонено — почему). Второй круг — только если принятые изменения существенны. Неразрешённое разногласие — короткий прямой вопрос пользователю с вариантами.
- Те же ворота при существенной смене плана по ходу работы.

### 5. Расход токенов

- Дефицитна квота Claude (35 % против 1–6 %). Claude — дирижёр и судья: замысел, решения, приёмка по сути, общение с пользователем. Объёмная работа — помощникам.
- Маршрутизация по умолчанию: код, тесты, работа с файлами, поиск по диску → Codex; длинные тексты, фактура, ресёрч, полное вычитывание больших файлов → Antigravity; второе мнение → оба.
- Claude не читает большие файлы целиком, если помощник может дать сжатую сводку со ссылками на строки; мост отдаёт компактные ответы постранично.
- `status` показывает квоты: Codex — % и время сброса из журналов сеансов; Antigravity — цифр нет, показывается число поручений и время за 5 часов и последнее исчерпание; Claude — со страницы claude.ai/settings/usage во встроенном браузере (после одного входа пользователя; иначе «не видно»).
- Пороги Claude: ≥ 70 % — экономный режим (проверки целиком отдаются помощникам, Claude смотрит только спорное; короткие отчёты); ≥ 90 % — закончить текущий шаг, записать состояние (п. 7), не начинать новое.
- Модели: механика — gemini-3.8-flash-medium; суждение — gemini-3.1-pro-high; Codex — по умолчанию.

### 6. Скилл

Один универсальный скилл `helpers` вместо `rabota-s-antigravity` (единый мост → единый порядок работы; особенности каждого помощника — отдельными разделами). Отдельный скилл под Codex не делаем: он дублировал бы 80 % текста и расходился бы со временем. `vtm-hronika` ссылается на `helpers`. Исходник скилла живёт в общем репозитории (п. 8), в Claude он устанавливается карточкой «сохранить скилл» — единственный ручной клик, ограничение платформы.

### 7. Исчерпание квоты без остановки работ

- Мост распознаёт исчерпание (Antigravity: quota / RESOURCE_EXHAUSTED / 429 / exhausted; Codex: turn.failed с usage limit, rate_limit_reached_type в журнале сеанса, «try again at …»). Поручение получает статус ЖДЁТ КВОТУ с временем сброса (если оно известно; иначе пробы раз в 30 минут), хранится на диске и само перезапускается после сброса; при перезапуске моста очередь поднимается заново.
- Разрешённая подмена: поручение только на чтение (review/text) с `fallback: true` может уйти второму помощнику; правки и задачи с записью — нет.
- Claude: всё состояние работы — в status.md («следующий шаг» заполняется до каждого долгого шага). В начале длинной работы Claude ставит напоминание в эту же беседу на время сброса своей квоты (запланированное сообщение); если работа к тому времени закончена — напоминание снимается. Результаты помощников, пришедшие, пока Claude стоит, лежат у моста и не теряются.

### 8. Без «мастер-чата»: общее состояние в репозитории

- Локальный git-репозиторий `C:\trio` (без GitHub — не нужен аккаунт и выход в сеть). В нём: код моста, общие правила (`AGENTS.md` — Codex читает автоматически; `GEMINI.md` — для Antigravity), исходник скилла, `lessons.md`, папка `works/` со status.md работ, папка `reviews/`.
- Любая правка инструментария (мост, правила, скилл): ветка `change/<имя>` → коммит автора → мост рассылает дифф двум другим (review) → их вердикты лежат файлами `reviews/<change>/<кто>.md` → слияние в main только при трёх «ПРИНЯТО» → скрипт развёртывания копирует main в живые места (C:\most, правила агентов; скилл — карточкой).
- Живая папка моста обновляется только из main — ровно идея пользователя: «папку обновлять, только когда все посмотрели».
- Мастер-чат не нужен: состояние живёт в репозитории, а не в переписке. Любой клиент (любой чат Cowork, приложение Codex, приложение Antigravity), открыв C:\trio, видит одно и то же: что идёт, что принято, какие уроки.
- Попутно: починить кодировку GEMINI.md Antigravity (перекодировать в UTF-8 без изменения текста) — иначе его правила не действуют.

## Поправка после разведки

Создать C:\trio не удалось (песочница Codex не пишет вне своей папки, у Claude доступ только к подключённым папкам). Предлагаемая замена: репозиторием становится сам C:\most. Ветка main в C:\most — живой мост (Claude запускает его отсюда). Правки ведутся в рабочих копиях git worktree `C:\most\.work\<change>` (исключены из репозитория), в main попадают только слиянием после трёх «ПРИНЯТО». Сторож: `status` сообщает, если в живой папке есть незакоммиченные изменения; git-хук на main не даёт коммитить без файлов ревью.
