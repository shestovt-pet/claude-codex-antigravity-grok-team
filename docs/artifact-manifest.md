# Проверка заказа изображений

Заказ задаётся явно, до генерации. Роли участников совещания не определяют список операторов. Для ночи 3: 19 исходных идентификаторов × `grok`, `codex`, `antigravity`, то есть 57 ячеек. Claude не добавляется автоматически.

Этап указывает `artifact_manifest` — путь относительно `work.folder`. Сам JSON заказа нужно включить в проверяемый материал этапа: изменение списка заказа или путей после согласования требует нового ревью. Валидатор сверяет именно переданный заказ, а не восстанавливает намерение человека из текста.

```json
{
  "schemaVersion": 1,
  "order": {
    "ids": ["chicago_items_wooden_comb"],
    "operators": ["grok", "codex", "antigravity"],
    "aspectRatio": [1, 1]
  },
  "artifacts": [{
    "id": "chicago_items_wooden_comb",
    "operator": "grok",
    "job": "номер-поручения",
    "parentJob": "unknown",
    "generatorService": "unknown",
    "providerReportedArtifactModel": "unknown",
    "promptSha256": "64 шестнадцатеричных знака SHA256 исходного промпта",
    "iterations": [{"iteration": 0, "instructions": "Дополнительные инструкции этой итерации"}],
    "path": "images/comb_service_model_unknown.jpg",
    "delivery": {"status": "delivered", "method": "CopyFromBox; затем локальное копирование"},
    "mime": "image/jpeg",
    "width": 1024,
    "height": 1024,
    "sha256": "64 шестнадцатеричных знака SHA256 файла",
    "visualReview": {"status": "accepted", "author": "имя проверяющего"},
    "metadataClaims": {
      "declaredGenerator": "Grok Imagine",
      "declaredModel": "unknown",
      "metadataSource": "C2PA файла",
      "signatureValidation": "not_checked",
      "trustValidation": "not_checked"
    }
  }]
}
```

Пример показывает схему, а не готовый заказ: отсутствуют две ячейки и настоящие хеши. `iterations` может быть пустым. `metadataClaims` и `order.aspectRatio` необязательны; остальные приведённые поля обязательны. Неизвестные job/parentJob/service/model обозначаются строкой `unknown`. Автор и положительный статус визуальной проверки обязательны. Идентификаторы и операторы сравниваются точно, с учётом регистра; дубликаты списков запрещены.

`validateManifest(manifest, root)` из `common/artifact-manifest.js` синхронно возвращает `{ready, errors, artifacts}`. `root` — абсолютная папка заказа. Ошибочный или неполный заказ даёт `ready:false`; исключения чтения отдельных файлов входят в `errors`. `readLocal(root, relative, limit)` читает обычный файл с ограничением размера и проверкой пути; его можно использовать для загрузки JSON (рекомендуемый предел 4 МиБ).

```powershell
node tools/verify-artifacts.js C:\project outputs\manifest.json
```

CLI выводит JSON; код 0 означает успешную проверку, 1 — неготовность/ошибку. Файлы не изменяются. Для каждого изображения предел чтения — 64 МиБ; для PNG такой же предел распакованных данных. Путь должен быть относительным, внутри корня, без ссылок/junction в компонентах. Каталоги, устройства, ADS, абсолютные пути, выход через `..`, отсутствующие файлы не принимаются.

Проверка требует ровно одну запись на каждую пару заказа, без лишних операторов, повторных ячеек и одинаковых байтов под видом отдельных версий. По локальным байтам вычисляются SHA256, MIME и размеры; затем сверяются расширение, заявленные поля и заданное соотношение сторон (точно, без округления). PNG проверяется по структуре, CRC и ограниченной распаковке IDAT; для нечересстрочного PNG также проверяются объём строк и номера фильтров. JPEG проверяется по структуре заголовков SOF/SOS и маркеру конца. Это не полноценное декодирование JPEG и не оценка художественного соответствия. Визуальное ревью остаётся отдельным обязательным свидетельством; авторство такого ревью сервер не удостоверяет.

`artifacts` ответа содержит наблюдённые характеристики файлов и поля происхождения из манифеста. `evidenceLevel: locally_observed_artifact` относится только к доставленным байтам. Модель из манифеста получает `modelEvidence: manifest_claim` или `unknown`, а не доверенную аттестацию. Вложенные `metadataClaims` всегда получают `evidenceLevel: metadata_claim`, `signatureValidation: not_checked`, `trustValidation: not_checked`: этот валидатор не проверяет подписи C2PA и не наследует утверждение `verified` из JSON. Название оператора, имя файла, продукт и сертификат не доказывают конкретную нейросеть. Разные операторы не означают разные подтверждённые модели изображений.

Для проверки возможности генератора требуется доставленный пробный файл, прошедший эти проверки и визуальное ревью. Описание инструмента или обещание ответа не заменяют пробу. Манифест не запускает генерацию и сам не подтверждает криптографически job, промпт или заявленного провайдера.
