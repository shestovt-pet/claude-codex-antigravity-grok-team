## Раздельное первоначальное развёртывание

- `--release-only` собирает архив выбранного коммита в `live`, устанавливает или копирует зависимости и выполняет настоящие MCP initialize/tools/list для трёх серверов. После успешных проб записывает `probe-ok.json`, затем публикует каталог релиза.
- `--node-modules-from <папка>` копирует готовые зависимости вместо `npm ci`; ссылки в копируемом дереве отклоняются. Этот путь позволяет работать без сети.
- В режиме сборки конфиги вообще не читаются. Данные блокировок, пробных запусков и кэш npm по умолчанию находятся в `live/.deploy-state`; `--state-dir` позволяет указать другую разрешённую папку. Архив и подготовленный каталог находятся в `live`. Имя канала блокировки репозитория не зависит от `--state-dir`, поэтому смена папки состояния не даёт второго владельца того же репозитория.
- `--config-only` требует явные `--release` и `--config`. Проверяет существование релиза, метку пробного запуска и файлы серверов; сохраняет посторонние поля и резервную копию `.prev`. Повтор на тот же релиз не заменяет прежнюю `.prev`. Путь основного репозитория берётся из метки релиза.
- Режим настройки пишет только в папки указанных конфигов (либо в явно выбранный `--state-dir` для блокировок). Релиз только читается. Несколько конфигов допускаются, но при ограничении записи одной папкой используются отдельные запуски.
- `--dry-run` доступен для обоих режимов без записи. Несовместимые параметры отклоняются.
- Раздельная установка не меняет `live/deployed.json`; текущие пути следует смотреть в конфиге и статусе. Релиз без метки автоматически не считается проверенным. Метка фиксирует успешную пробу, но не является подписью или защитой от последующей ручной подмены содержимого.
