## Уточнения и отступления

- В `team_rules` используется зафиксированный хеш main вместо повторяющегося `git show main:...`; содержимое — строго из одного коммита main.
- План изменяется полем `plan_change` с пояснением; сервер сам дописывает `plan_changes`, клиент не может переписать историю целиком.
- Для ревью требуется **оба** хеша в поручении. Дополнительно отклоняются задания Codex с записью или продолжением прежнего сеанса, задания Antigravity вне режима review, архивные задания и несовпадение хеша сохранённого результата Antigravity. Это выполняет порядок общего правила о новом сеансе проверяющего.
- Установка: `npm ci --omit=dev --ignore-scripts`; установочные сценарии зависимостей не исполняются. В текущем наборе зависимостей используются готовые JavaScript-пакеты.
- Архивирование отклоняет Git-ссылки и подмодули, чтобы извлечение не могло записать за границей релиза. При необходимости такой структуры её поддержку нужно согласовать отдельно.
- `works/*.json` и `works/status.md` добавлены в `.gitignore`: текущее состояние работы не должно делать код грязным и блокировать слияние. Карточки сохраняются на диске основного репозитория.
- В адаптерах части 1 внесены только необходимые дополнения для безопасной проверки запуска и сообщения версии/пути через канал владельца. Общая функция `startOwner` получила необязательные сведения о процессе.
- Диагностические архивы и подготовительные каталоги развёртывания сохраняются; автоматическая очистка не добавлялась. Откат возвращает записи серверов из `.prev`, сохраняя остальные текущие поля конфига.

## Известные ограничения и дальнейшая проверка

- Живые конфиги Claude и работающий мост не менялись. Первоначальную установку выполняет Claude после приёмки; CLI принимает явно выбранный коммит, а сервер deploy требует его наличия в истории main. Приёмка первоначального коммита остаётся внешней процедурой.
- Данные квот могут отсутствовать или устареть; состояние владельца не подменяется одним PID. Версия помощника без доступного канала владельца не объявляется проверенной.
- Блокировки координируют операции серверов с одинаковым хранилищем. Они не защищают от ручного изменения файлов/Git вне этих серверов; перед изменениями есть повторные проверки, но полную транзакцию с произвольным внешним редактором файловая система не предоставляет.
- Компенсация конфигов покрывает ошибки операций; внезапное отключение питания/принудительное убийство процесса между заменами файлов не моделировалось. Если пользователь изменил уже переключённый конфиг, сервер не затирает его правку и сообщает о частичном обновлении.
- `live/deployed.json` — отметка последнего развёртывания, а не доказательство запущенного процесса. После rollback текущий выбор виден в конфигах; старые процессы сменятся только при перезапуске Claude.
- Реальная установка зависимостей в новом релизе, запуск из живых конфигов, загрузка проектных правил помощниками и работа после перезапуска Claude остаются живыми приёмочными испытаниями. Linux в этом сеансе не проверялся.
- Проверки возобновления исполнителей выполнялись с поддельными исполнителями в части 1. Доставка напоминаний Claude в этом сеансе не проверялась; поведение при действительно исчерпанной квоте Claude не проверено.
