## Спорные места и отступления

1. **SDK**: ТЗ говорит о 1.29.x, однако предоставленные package-lock.json и node_modules содержат **1.30.1**. Сохранён исходный диапазон `^1.29.0` и фактическая зависимость lock-файла. Проверено на 1.30.1 и zod 3.25.76; на 1.29.x не проверено. Не подменял lock-файл неподтверждённой версией и не делал npm install.
2. **429 agy**: в сжатом ТЗ «429 в error» назван квотой, одновременно требуется временный 429 без признаков квоты. Принято различение из замысла: RESOURCE_EXHAUSTED/quota exceeded — квота; голый 429/rate limit — временная ошибка (3 повтора). Это решение требует внимания при ревью.
3. **continue_id после записи**: явное продолжение разрешено также из НУЖНО РЕШЕНИЕ, как предусмотрено разделом В5 замысла, хотя сжатый список допустимых состояний в ТЗ его пропускает. Требуются threadId, прежние folder/write и отсутствие неподтверждённой остановки.
4. **Совместимость Antigravity**: публичный API новый; внутренние поля старых карточек (`rezhim`, `papka`, `work` как исходный материал) сохранены. Название общей работы записывается в `workName`, этап — в `stage`. common/format учитывает это. Для Codex общая работа — строковое поле `work`.
5. **Остановка дерева процессов**: в этой песочнице taskkill /T ограничен. Проверено честное отображение неподтверждённой остановки и остановка собственного основного процесса; полную остановку потомков здесь подтвердить нельзя. Дополнительная инвентаризация процессов через Get-CimInstance также получила «Отказано в доступе» (0x80041003); отсутствие всех оставшихся тестовых потомков независимо не подтверждено. Если осталась карточка с неподтверждённой остановкой записи, снятие блокировки после ручной проверки требует отдельной процедуры оператора; инструмента такого подтверждения в ТЗ нет.
6. **Запрет удалений**: тестовый режим MOST_TEST_KEEP сохраняет артефакты и отключает очистку. Три проверки удаления пропускаются явно. Производственная очистка не выдаётся за проверенную в этой среде.
7. **Точные даты**: распознаются корректные даты/epoch; неразбираемая дата не превращается в немедленный запуск — применяется интервал пробы. Локальные человекочитаемые формулировки CLI без однозначной даты требуют живой проверки.
