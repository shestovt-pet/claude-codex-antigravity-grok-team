## Исправления

1. **Очистка незавершённых заданий.** Antigravity удаляет по возрасту только задания в окончательных состояниях `done/applied/failed/cancelled/lost` либо каталоги без карточки. Все другие состояния, включая неизвестные и повреждённые карточки, сохраняются. Та же проверка применяется к входным каталогам и освобождению входных файлов после запуска. У Codex нет возрастной очистки карточек или материалов; единственное удаление в его адаптере — уборка временного файла неудачной записи карточки.
2. **Git при другом владельце репозитория.** Для чтения при развёртывании введён ограниченный вызов `deployGit`: `rev-parse`, `archive`, `ls-tree`, `cat-file`, `show` получают `-c safe.directory=<канонический корень>`. Другие команды отклоняются. Значение `*` не используется, глобальные настройки Git не меняются. Обычные операции team не получают это исключение автоматически.
3. **Проверка прежнего сервера перед откатом.** Локальные пути команды и файлов в аргументах восстанавливаемых серверных записей из `.prev` проверяются перед записью. Отсутствующий файл даёт отказ по конкретному конфигу без его изменения; следующие конфиги обрабатываются. Команды без пути, например `node.exe` или `npx`, остаются командами из PATH. Добавлен `--config-only --rollback --config <файл>` с блокировкой рядом с конфигом и без обращения к Git. `--state-dir` в этом режиме допускается.
4. **Первый переход до слияния.** `--release-only` принимает имеющийся в репозитории коммит вне `main`; регрессия подтверждает это и отказ обычного `team_change deploy` для того же коммита. README описывает порядок: fetch кандидата, сборка, переключение конфигов, перезапуск Claude, живые проверки, затем ff-only на тот же коммит. Старый `C:\most\index.js` до живой проверки сохраняется.
5. **Отрицательные вердикты.** `team_change verdict` принимает `НЕ ПРИНЯТО`, только если последняя строка завершённого задания соответствует `НЕ ПРИНЯТО: N …`, N больше нуля. Проверки режима ревью, пары коммитов и хеша результата Antigravity сохранены. Слияние остаётся доступно только с положительными голосами либо предусмотренной заменой пользователя.
6. **Мёртвый владелец.** `codex_status` использует нормализацию для `running/cancelling/stop_unconfirmed` и показывает потерянные задания. `team_status` применяет такое же отображение: запись требует решения, чтение считается потерянным. Общий формат больше не скрывает эти состояния за отметкой неподтверждённой остановки; предупреждение выводится отдельной строкой.
7. **Исчезнувшие карточки.** ENOENT после перечисления пропускается в списке Codex, его очереди и статусе, списке поручений team и списке работ. Другие ошибки не маскируются как исчезновение файла.
8. **Пробелы и окончания строк.** Устранены замечания исходного `git diff --check 8905a00 HEAD`: README, два старых отчёта, две страницы правил и прежний журнал части 1. Исполняемый старый код ради пробелов не переписывался. В общих правилах также уточнено соответствие последней строки выбранному вердикту.

Новые регрессии:

- Antigravity: реальное файловое поручение переходит в ожидание квоты. Даты ожидания и входной папки состарены на двое суток, карточка — за предел 30-дневного хранения. Выполняется сама функция очистки с подменой удаления на журнал попыток: попыток удаления незавершённых карточек и материалов нет, окончательные состояния попадают в очистку. Сервер перезапускается, поручение повторяется, сохранённые материалы совпадают побайтно. Физическое удаление в тесте не выполняется из-за ограничения сеанса.
- Codex: состаренное на двое суток ожидание квоты с текстовым файлом возобновляется после перезапуска с сохранённым материалом. Пропажа карточки после перечисления воспроизведена через ENOENT; очередь и статус продолжают работу. Для трёх состояний мёртвого владельца проверены оба режима — чтение и запись.
- Откат: отсутствующий путь прежнего сервера, сохранность отказавшего конфига, успешное восстановление второго; отдельный CLI-откат из папки конфига с запретом записи Node вне этой папки.
- Коммит вне main: сборка разрешена в bootstrap, обычное развёртывание team отклоняется.
- Отрицательные голоса обоих помощников записываются, ложное положительное принятие отклоняется, слияние блокируется до действительных положительных голосов.
- Пропажа карточек поручений и работ не ломает team.
