# Исправления trio-v4 по ревью кандидата e1bf31f

Запрос пользователя: #2bbf4317. Основание: замечания Codex b8d28417 и Antigravity mujhdl4k. Работа выполнена в `C:\most\.work\trio-v4`; рабочая установка не развёртывалась.

## Что исправлено

1. **Перенос хранилища.** Незавершённые задания без результата сохраняют своё состояние, владельца и имеющиеся файлы; карточка получает отметку «перенесено без результата». Обычная проверка владельца остаётся следующей операцией. Завершённые задания (`done`, `applied`) без результата либо с несовпадающим объявленным хешем сохраняются в `state/quarantine/<id>` со состоянием `migration_damaged` / «ПЕРЕНОС: ПОВРЕЖДЁН». Исходная карточка и доступные файлы сохраняются внутри карантина, причина — в карточке карантина и `migration.log`. Ошибка отдельного комплекта не останавливает остальные задания и запись метки готовности. Явно моделируемое прерывание процесса по-прежнему не создаёт метку. Задание из карантина не принимается как голос ревью, в том числе при наличии другой действующей карточки с тем же номером. Ссылки за пределы источника не обходятся.
2. **Переход с d99824c.** Новый код запускается с прежним `MOST_STATE_DIR`. При повторном deploy того же коммита метка на три сервера допускается только как основание для повторного пробного запуска: четыре основных сервера и шесть гостевых подключений. После успешной проверки обновляется метка, выполняется перенос, переключаются настройки Claude, Codex и Antigravity, планируется перезапуск с ожиданием четырёх серверов в `C:\most\state`. При неудачной проверке прежняя метка и настройки сохраняются. Код существующего релиза повторно не собирается.
3. **Передача работы.** Перед решением о claim карточки Codex и Antigravity перечитываются под их штатными замками, проверяется фактический владелец. При подтверждённой потере владельца выполнявшиеся поручения записываются как «ПОТЕРЯНО». Неизвестный либо живой владелец не объявляется погибшим. Проверки часа без активности и номера редакции сохранены; Grok проходит прежнюю проверку своего состояния.
4. **Тексты.** README и правила согласованы с четырьмя серверами и Grok в гостевых подключениях. Описан двухшаговый переход. Урок Н2 исправлен: этапы не принимались, статус «в работе» не отправлялся, сообщения исполнителя до пользователя не дошли. В общих правилах указан способ записи совещательного голоса: `team_change verdict/design`, `who=grok`, `job_id` с номером Grok-задания.

## Ограничения проверки и передача Claude

Пять пропусков обусловлены средой: три проверки удаления/очистки отключены через `MOST_TEST_KEEP=1`, одна проверка остановки дерева процессов недоступна из-за запрета `taskkill /T`, одна проверка файловой символической ссылки недоступна на Windows. Проверки переходов каталогов выполнены.

Настоящий Claude Desktop не закрывался: в проверке развёртывания запуск сценария перезапуска заменён тестовым обработчиком с проверкой сценария и подтверждения запуска. Сами MCP-серверы запускались настоящими процессами. Развёртывание в рабочей установке и проверка настоящего перезапуска остаются стадией выпуска после ревью, а не результатом этого теста. Функциональных отступлений от поручения нет.

В `.git` этой рабочей копии изменений не выполнялось, исходные файлы не удалялись и не переименовывались. Тесты используют отдельные временные репозитории. Коммит не создан. Claude или серверу team необходимо зафиксировать перечисленные файлы после проверки; удалений или переименований исходного кода не требуется. При необходимости отдельно очистить оставленные этим прогоном `tests/.tmp-*` и временные `most-part2-*` после сверки журнала и завершения процессов; автоматическая очистка отключена.

Порядок живого выпуска: приёмка → фиксация исправленного кандидата → независимые ревью → слияние → старый deploy точного коммита с перезапуском → новый deploy **того же коммита** с перезапуском → `team_status` и проверка единого хранилища, четырёх серверов и гостевого Grok. Оба вызова deploy выполняет Claude; действий пользователя не требуется.
