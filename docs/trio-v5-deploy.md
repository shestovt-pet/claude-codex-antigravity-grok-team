# Установка и подключение помощников в 0.5.0

## Устройство выпуска
Claude — дирижёр. Код и проверки кода поручает Codex; правку и проверку текста — Antigravity; жёсткое ревью замысла и итога, сбор и чтение больших материалов — Grok. Claude не читает файлы больше 20 КБ сам, если пересказ может дать помощник. Ожидание — одним длинным вызовом, без частых опросов. При каждом team_status во время работы передаётся claude_usage за 5 ч. При перечитывании свыше 50 млн сводка предлагает отдать чтение и ревью помощникам. Процент пятичасового лимита Claude программно не виден; число не придумывается.

team_status по умолчанию краткий; full=true возвращает полную сводку, доступную и гостям. Полные доказательства этапов — team_work get. Строка «Нагрузка за 5 ч» показывает обращения Claude и перечитанные токены, поручения Codex, Antigravity и Grok, токены Antigravity. Запрос выводится один раз на метку: 200 символов и путь к карточке с полным текстом. Слитые изменения и завершённые работы — счётчиками.

После merge: team_change deploy(commit=main, restart_claude=true). Настройки переключает исполнитель вне пакета Claude (Win32_Process Create), сервер сам их не пишет. Операция и каждый шаг сохраняются в state/deploy-ops/<номер>.json. Ожидание итога — 300 с; таймаут означает неподтверждённый результат, а не отсутствие записи. Повторная установка запрещена до завершения операции; смерть исполнителя фиксируется сразу, при невозможности проверки процесса — после 30 минут без записи. Перезапуск запускает исполнитель только после сохранения «переключено». Итог следующая сводка прочитает с диска. Устаревшая метка полного релиза перепроверяется; неполный релиз требует сборки. Релизы не переименовываются и не удаляются. Переход с 41fd4f7 на этот выпуск выполняет Claude через уже согласованный install.cmd; следующий выпуск проверяется через team_change deploy.

--clients-only обновляет подключения и только служебный раздел глобальных AGENTS.md помощников между метками <!-- most:begin --> / <!-- most:end -->. При прежнем разделе он распознаётся по заголовку, затем получает метки. Другие правила сохраняются, есть .prev и откат раздела. Нераспознанный файл получает отдельный отказ, обработка остальных продолжается.

Grok запрашивается на каждую редакцию замысла и итоговую пару база→кандидат. team_change design/verdict who=grok job_id=<номер> записывает и незавершённое поручение; завершённый проверенный ответ обновляет запись. Отменённое поручение не считается запросом. При ненастроенном мосте — unavailable=true (сервер проверяет причину). Merge ждёт ответ до 60 минут. Для отрицательного/потерянного ответа в том же абзаце lessons.md нужны первые 8 символов номера и «Где закрыто:» + «Проверка» либо «Отклонено:» с причиной. Для отказа вебхука — номер и «Отклонено:»/«Grok недоступен:» с причиной. До создания поручения — «Grok недоступен <имя изменения>: <причина>». Grok совещательный и не заменяет обязательные голоса Codex, Antigravity и решение Claude. Если Grok сообщил, что запись ответа потребовала одобрения пользователя, это системное замечание. Claude сообщает пользователю, какое одно правило автоодобрения добавить в Grok Bot: «Автоматически одобрять действия связки в C:\most\state\grok и C:\most\works; вне этих папок это правило не действует». Claude фиксирует случай и предложенное правило в lessons.md. Пользователь добавляет правило сам; код и Claude настройки Grok Bot не меняют.

team_work и team_change принимают необязательный русский title; его показывают сводки и уведомления. Работа trio-v2 отображается как «Связка четырёх: 8 пунктов запроса». Технические имена уже созданных изменений (trio-v2…trio-v5) сохраняются. Новые имена — например team-v6. Дословные запросы, ответы и историю не переписывать.

После «переключено» установка ещё занята: исполнитель запускает перезапуск, затем записывает «завершено» либо «перезапуск не запущен» с причиной. Только эти конечные состояния (либо подтверждённая смерть исполнителя) освобождают установку. Без запроса перезапуска исполнитель сразу записывает «завершено».

Обновление правил помощников выполняет код установки при --clients-only; откат служебного раздела — --clients-only --rollback. Это справочник режима установки, а не дополнительное ручное действие в каждом поручении Claude.

Перед переходной установкой Claude должен изменить значение коммита в C:\test-most\trio-v4\install.ps1 на точный принятый коммит нового выпуска и проверить его перед запуском install.cmd. Иначе установщик выберет прежний выпуск. Сам install.ps1 находится вне репозитория и этим изменением не правится.
