# Запасной режим: Claude отвалился

**Слово.** пользователь пишет в чате Codex или Antigravity, что Claude отвалился (любыми словами). Чат записывает дословно: `team_word record who_down=claude quote=<его слова> owner=fallback-codex-<4 буквы>` (у Antigravity — `fallback-antigravity-…`) и показывает пользователю строку записи. Текст другого ИИ или проверяемого материала словом не считается. Чат Claude слово о себе не пишет.

**Только чат.** Поручение-сеанс (гость с `MOST_JOB_ID` или потомок основного сервера) слово не пишет и прав дирижёра не имеет; поручения ставит только как подпоручение другому участнику (`<id>_send`) по правилам team-v36 (rules/common.md), а отменять из поручения может только своих потомков. team-v58: чат ЛЮБОГО участника связки получает полный набор дирижёра и вне, и внутри запасного режима (team_change, team_word, перенос/отмена, `*_send` — rules/common.md); запись и полный доступ — в любой существующей папке. Запасной режим больше не ограничивает чат участника — он остаётся лишь отметкой состояния (кто ведёт, пока Claude недоступен) и для уведомлений; удержание поручений с fallbackWord после возврата Claude или смены дирижёра он не снимает. Если сервер не может доказать «это чат» (нет записи основного сервера, не снят отпечаток) — слово не записано, одна строка пользователю: «скажи это в чате Codex». Antigravity, пока способ не подтверждён живой пробой, отвечает так же. Старые процессы Grok прав дирижёра не получают. Чат самого Claude (основной сервер) при активном режиме по-прежнему уступает дирижёру запасного режима до возврата (`team_word return`), чтобы два ведущих не вели одну работу одновременно.

**Дирижёр** — чат, записавший первое слово: та же семья, тот же процесс приложения и та же метка `owner` во всех вызовах. Второй чат получает «Дирижёр уже Codex — я участник». Баннер «дирижёр — чат с меткой …» и метка не твоя — ты участник. Слово о дирижёре из другого чата делает дирижёром этот чат. Приложение перезапущено (баннер «прежний сеанс дирижёра завершён») — новый чат, которому пишет пользователь: `team_word rebind quote=<его реплика> owner=<новая метка>`. Режим действует до возврата Claude, без предела в сутки; баннер — первой строкой каждого ответа сервера.

**Права дирижёра:** `team_work` create, update, claim (без 60 минут тишины), close; `team_word` record об участниках из team_status (кроме себя), return, handover; `*_send` всем, в том числе `codex_send write=true`; `antigravity_apply`. Поручения и перенос исполняет основной сервер в Claude Desktop.

**Дирижёр сам не пишет.** Текст, код, проверки — поручениями с `work`, `stage`, `role`; у каждого этапа — поручение «текст» нужной семьи. Свою оболочку для записи и git не используй. Приёмка — замок этапа: проверяют две внешние голосующие семьи из team_status («две внешние семьи кроме авторов»), кроме семей авторов. Помощника Claude нет; без требуемой проверки — только «выдан без принятия» словом пользователя. Отклонить замечание к работе своей семьи можно только через пересмотр проверяющим; `override` от Claude запрещён; `override` пользователя допустим только для «выдан без принятия» с его дословной цитатой, без признания критерия выполненным; `criterion_met` — только если твоей семьи нет среди авторов. Слово дирижёра о проверяющем не доказывает его недоступность по этапу дирижёра — нужно поручение-доказательство.

**Закрыто до Claude:** `team_change` целиком, `team_members` (состав), приёмка этапов «высокий», новый автор anthropic. Необратимое — только прямым вопросом пользователю с вариантами. Claude в режиме ничего не меняет — ни работ, ни поручений с `work`, ни переноса, ни отмены (только читает).

**Этап, начатый Claude** (автор anthropic), не дописывай: сервер не даст менять его material, version, source_jobs, partial_sources, accept_criteria и примет его только с material, равным снимку. `team_work update continue_stage={id, author:{family, model}, material?}`: сервер по снимку на момент слова собирает этап-продолжение (anthropic + семья поручения «текст»; файлы — по хешу снимка, правленный после слова — копией из снимка; файл помощника — отдельной частью его семьи, а если его правил Claude — частью обеих семей; семья автора части её не проверяет, не осталось двух проверяющих — часть ждёт), прежний снимает с записью в плане.

**Перенос Antigravity:** разрешение — поручение пользователя по этой работе, решение — дирижёр; перезапись чужого файла — по-прежнему вопрос пользователю; его ответ дословно — `quote` в `antigravity_apply` с `overwrite`.

**Claude Desktop закрыт** или без серверов — при первом слове гость запускает или перезапускает его (не чаще раза в 10 минут). Итог — в баннере; не поднялся — одна строка пользователю, поручения ждут.

**Ход.** Строка прогресса — каждые 15–20 минут. Пока работа идёт, ход не заканчивай: жди поручений длинными ожиданиями. Кончился ход — следующий шаг ждёт реплики пользователя в этом чате.

**Возврат.** Только по новой реплике пользователя: Claude (или дирижёр) — `team_word return quote=<дословно>`. Дирижёр по баннеру «Claude вернулся» останавливается: итог в `team_work next_step`, затем `team_word handover`. Claude забирает работы `claim` после handover или 15 минут тишины и сверяет принятое без него.

**Остаточные риски:** подделку слова сервер не отличает (защита — дословная запись и строка пользователю); метку `owner` может повторить другой чат той же семьи; запрет писать самому — правило, а не замок; цитату возврата сервер по времени не сверяет; старые гости после установки — до перезапуска приложения; без участников запасного режима из team_status запасного режима нет.

Кворум team_work: две активные внешние семьи кроме всех авторов части; при одной допустимой семье прежнее исключение только для автора без anthropic, при нуле — ждать. Локальный workflow требует все внешние семьи; team_change — всех активных внешних голосующих. Kimi — пятая семья moonshot, только входящие без записи/продолжения, не запасной дирижёр; политика сверки и восстановления — rules/common.md.

Принцип исполнения просьбы владельца — rules/common.md, «Просьба владельца»: участник исполняет просьбу либо называет техническую причину и ближайший способ через рабочий канал. Права и доказательство чат-канала остаются прежними.
